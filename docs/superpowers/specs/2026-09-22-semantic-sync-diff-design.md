# MyKeymap 语义化配置差异设计

## 背景与目标

当前 GitHub 配置同步页面以 Git unified diff 展示 `data/config.json` 的变化。虽然该输出精确，但它暴露了实现细节，普通用户很难从 JSON 行判断快捷键、缩写和动作在本地与远端分别做什么。

本功能将“查看差异”改为面向 MyKeymap 配置语义的双列对比。页面默认只展示发生变化的配置项，以“本地”和“远端”描述其实际行为，同时保留默认折叠、已经脱敏的原始 JSON diff 作为高级排查入口。

## 用户体验

差异按配置区域分组：

- 快捷键映射
- CapsLock 缩写
- 普通设置
- 无法归入上述区域的其他配置

每条差异包含：

- 可读路径，例如 `CapsLock 缩写 → ty` 或 `快捷键层 *3 → *0`
- 变化类型：新增、删除或修改
- 本地描述
- 远端描述

不存在的一侧显示“未配置”。新增使用绿色标签，删除使用红色标签，修改使用黄色标签。

示例：

```text
CapsLock 缩写 → ty  [修改]
本地：打开程序「Typora」
远端：运行脚本「testy」
```

页面底部提供“展开原始 JSON 差异”，默认折叠并支持复制。

## 架构

### 后端

`GET /sync/diff` 继续负责读取本地配置与镜像仓库中的远端配置。后端完成以下处理：

1. 将两份完整配置解析为 JSON。
2. 在任何差异计算前递归脱敏敏感字段。
3. 按 MyKeymap 配置结构匹配 keymap、缩写键和动作。
4. 生成结构化差异列表。
5. 使用两份已脱敏配置生成原始 unified diff。

接口响应扩展为：

```json
{
  "status": "conflict",
  "differences": [
    {
      "group": "CapsLock 缩写",
      "path": "CapsLock 缩写 → ty",
      "kind": "modified",
      "local": "打开程序「Typora」",
      "remote": "运行脚本「testy」"
    }
  ],
  "rawDiff": "..."
}
```

`kind` 只允许 `added`、`removed`、`modified`。结构化差异的顺序稳定：先按配置区域，再按可读路径排序。

### 前端

前端不再解析 JSON 或猜测动作含义，只消费结构化响应：

- 按 `group` 分组渲染。
- 每条差异使用本地/远端双列卡片。
- 根据 `kind` 显示中文颜色标签。
- `rawDiff` 放入默认折叠的高级区域。
- 空差异显示“本地与远端没有可显示的配置差异”。

## 语义匹配规则

### Keymap

Keymap 优先使用稳定 `id` 匹配；缺少 `id` 时使用 `hotkey` 与父级标识组合匹配。匹配后分别比较：

- 是否启用
- 延迟
- 禁用条件
- 子热键与缩写动作

数组顺序变化本身不产生差异。

### 动作

动作优先使用 `comment` 作为可读说明，并结合动作字段补足含义。至少支持：

- 打开程序或激活窗口
- 运行 MyKeymap 内置动作
- 模拟鼠标或滚轮动作
- 按键映射
- 发送按键/文本
- 执行 AHK 代码

例如：

- `actionTypeID: 1` 且 `target` 为 Typora 快捷方式：`打开程序「Typora」`
- `actionTypeID: 5` 且 `remapToKey` 为 F10：`映射到 F10`
- `actionTypeID: 8`：优先显示注释，否则显示 `执行 AHK 代码`

同一快捷键包含多个动作时，按原动作顺序生成编号描述。无法识别的动作显示 `未知动作（类型 X）`，并只附带脱敏后的非空关键字段摘要。

### 普通字段

布尔值使用“启用/禁用”，毫秒值附加单位，缺失值显示“未配置”。未建立专门翻译规则的字段使用 JSON 路径和经过格式化的值作为保底描述。

## 安全与错误处理

- token、secret、password、apiKey、privateKey、accessKey、passphrase、cookie、authorization、credential 等敏感键在语义解析和原始 diff 前统一脱敏。
- 原始配置无法解析为合法 JSON 时，接口返回结构化错误，不返回原始文件片段。
- Git 或文件系统错误继续使用通用错误消息，不向浏览器暴露凭据或本机路径。
- 临时差异文件使用受限权限，并在请求结束时删除。
- 未知配置结构不会阻止整个差异页面；它使用通用保底描述。

## 测试

后端自动化测试覆盖：

- 快捷键动作修改
- 缩写新增与删除
- 启用状态和延迟修改
- 动作替换，例如 Typora 改为脚本动作
- 数组仅重新排序时不产生噪声
- 未知动作类型的保底描述
- 格式错误时安全失败
- 敏感字段不会出现在结构化差异或原始 diff 中
- 原始 diff 仍能展示多行格式化 JSON

前端验证覆盖：

- 生产构建成功
- 中文分组与变化标签正确
- 本地/远端双列展示
- 不存在的一侧显示“未配置”
- 原始 JSON 差异默认折叠并可展开复制

## 范围边界

本次只改进差异展示，不改变冲突判定、备份、推送、拉取或“保留本地/使用远端”的行为。不会实现逐项合并；冲突解决仍然以整份本地配置或整份远端配置为单位。
